# `shared/` —— 工具注册表

`tools.json` 是 **Java Policy 引擎和 Python 引擎共读的同一份工具清单**（§4.4）。
字段的含义、三个取值的口径、以及它如何决定审批等级，**一律以 `DEV_DOC.md` 为准，这里不重复**
（理由同 `ARCHITECTURE.md`：复制细节必然漂移，见 §14.2 的"镜像双后端"）。

这里只记 **`DEV_DOC` 里没有、而这份文件自己产生的决定**。

## ⚑ 故意不缺的一条：`restaurant_booking`

**清单里没有 `restaurant_booking`，这是设计，不是遗漏。**

§1.2 的示例图里有一条：

```
└─ 🔴 预订米其林餐厅          [blocked · 无可用工具]
```

这条演示状态**靠的就是"这个工具不存在"**。有人觉得清单缺东西、顺手把它补上，
§1.2 那个例子就**悄悄没了** —— 而且是静默的，没有任何东西会报错（§14.2 #13）。

**所以：要加这个工具，先改 §1.2 的例子，别只改这里。**

## `input_schema` 全是 `null`，是故意的

留着字段不写（而不是删掉字段），是为了让"**还没定**"和"**忘了填**"看起来不一样。

A4 真写工具实现时再补 —— 现在写等于**提前把参数定死**，而参数会随实现改。
（其中三个工具的实参形状，可以从 `frontend/src/mocks/` 里的 `evidence.args` 看出个大概，
但那只是 mock 作者的示意，不是契约。）

## 拿不准的一律从严

`side_effect` 写宽了，代价是**该拦的没拦**；写严了，代价只是**多问用户一次**。
所以 A0 阶段凡是说不准的，一律按更严的一档填，等 A4 对齐真实实现时再放宽。

同理：**读取时遇到不认识的 `side_effect` 值，应当按最严处理（当 `irreversible`）或直接启动失败**
—— 现在拼错一个字母（比如写成 `read-only`）是没有任何东西会拦的，而它一路决定要不要拦住一次划钱。

## `description` 的文案属于 Prompt

它会被整份发给模型（§3.4），模型**就是靠它**选工具的 —— 所以它是 Prompt 的一部分，
受 §13 第 8 条"Prompt 全部自己写"管。目前这份是草稿。

清单里最危险的一对是 **`fx_rate`（只读）和 `currency_exchange`（真的动钱）** ——
名字长得像、后果差得远，两条 description 里的"何时别用"就是为这种配对存在的。
