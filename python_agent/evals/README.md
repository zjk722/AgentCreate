# `evals/` —— 评测（§12 的 **A1**）

**这里放「怎么判断模型吐出来的东西好不好」。**

它**不在 `app/` 里面** —— 评测不是产品代码，不该跟着引擎一起发出去。

> ⚠️ **位置以 `DEV_DOC` §11 为准**：`python_agent/evals/`，与 `app/` **平级**。
> `ARCHITECTURE.md` 的目录树把它画在 `app/` 下面 —— 那是**复制细节必然漂移**的一次实例
> （它在自己开头就警告过这件事）。已记进 v0.7 的清单。

## 文件

| 文件 | 干什么 |
|---|---|
| `corpus.json` | ⭐ **12 颗种子**：题目 + 期望（§8.3）。**内容由人写**（见下面"归属"）|
| `inputs/` | 长文的题目放这儿，`corpus.json` 里只写路径 —— **800 字 / 3000 字的输入塞进 JSON 没法读也没法写** |
| `runner.py` | 跑一遍、按断言判、**退化时非零退出码**（§8.4）|
| `judges.py` | 第三层用的裁判（LLM-as-judge）|

## ⚠️ 为什么 `corpus.json` 里没有注释

**JSON 不支持注释。** 所以"每格什么意思、为什么这么定"一律写在这里 ——
和 `shared/README.md` 承接 `tools.json` 是同一个安排。

## 一格一格说明

| 字段 | 干什么 | 谁执行 |
|---|---|---|
| `id` | 报告里点名用 | —— |
| `tier` | `green` / `yellow` / `red`（§8.3 的三档）。⚑ **它决定"允不允许波动"**：🟢 命中率够就行；🔴 **一条都不许倒退** | runner |
| `goal` | 题目。长文写成 `"inputs/xxx.txt"` | —— |
| `limits` | 喂给 `plan_goal()` 的两个上限。⚑ §8.3 那句"扇出 ≤ 6"**就是** `max_children: 6` | —— |
| `structure` | 第一层：**容许哪些类 warning** + 节点数范围（`error` 恒为 0，见下）| **脚本** |
| `distribution` | 节点的**分布**：每种 assignee 几个（§8.3 种子 #2 的"含 agent/user 分类"就是这个）| **脚本** |
| `coverage` | 第二层：**方向命中率** —— 每项是**一组同义词**（§8.1 说每条人工标 3–5 个）| **脚本** |
| `must_not_match` | 第四层：**标题里不许出现的东西** —— 一组正则。只用来钉「**不编造**」那一条（见 `seed-04`）| **脚本** |
| `semantics` | 第三层：一句话问 judge。**没有就填 `null`** | **模型** |
| `note` | 出处 / 为什么这么定（自由文字，给人看）| —— |

### `structure` 只有两格 —— `allowed_warnings` 是**白名单**（2026-09-18 改的）

```json
"structure": {
  "allowed_warnings": [],
  "node_count": { "min": 3, "max": 15 }
}
```

**① `error` 恒为 0 —— 它是通用规则，不在每条里重复。**

`error` 的意思就是"这张图不能开工"（§7.1），所以**没有任何一条种子该容忍它**。
而把它写进 12 条数据里，就成了一份"要同步 12 遍的副本" —— 所以它归 runner，
`corpus.json` 里**不再有 `max_errors` 这一格**。

> ⚑ 那"**期望有一个 error**"的用例呢？→ 它属于 `tests/test_validation.py`，**不属于这里**。
> 因为 **corpus 测的是【模型】**，而"校验器会不会把错报出来"是**代码**的测试。两件事，别混。

**② `allowed_warnings` 是白名单 —— 没写进去的种类，一律不许出现。**

为什么是白名单，而不是黑名单（`forbidden`）？**因为默认方向不一样**：

| | 一条**新规则**上线时（比如以后加了 `W_TOO_MANY_LEAVES`）|
|---|---|
| **白名单**（本文件用的）| 所有种子**立刻开始检查它** ✓ |
| 黑名单 | 所有种子**默默容忍它** —— 没人会因此变红 ✗ |

⚑ 这和 §9.1 那条「**默认拒绝** —— 拦截器覆盖 `/api/v1/**`，`@Public` 显式放行」
是**同一个原则**。"默认放行"正是这个项目一路在防的东西：
一条新告警出现了，却**没有任何东西因为它变红** —— 那不就是没人看着吗。

⚠️ 所以"允许某类 warning"必须**显式写出来**：

```json
"allowed_warnings": ["W_DUPLICATE_SIBLING"]     // 容忍兄弟重名；别的种类一概不许
```

**为什么不再用「总共不超过 N 个 warning」**（原来的 `max_warnings: N`）：
它同时**太松**又**太紧** —— 一条 `W_DEPTH_EXCEEDED`（违反"深度 = 3"）也能占掉额度；
而两条无害的 `W_DUPLICATE_SIBLING` 却会让它红。
**§8.3 的断言全是按【具体的点】说的，不是按数量说的。**

### `coverage` 的 `must_contain`：每一项是**一个方向**（一组同义词）

```json
"must_contain": [
  ["机票", "航班"],     // ← 这是一个方向，两种说法都算
  ["酒店"],
  ["汇率"]
]
```

**为什么不是一个词一串**：模型对同一个概念有**多种说法** —— 实测要「机票」，
它说「往返航班」。如果平铺成一串词，一个概念会占掉**两个名额**：
命中一次算两次，**命中率会虚高**。

所以同义词必须归到同一组，**命中任一即算这个方向中**。
命中率 = **命中的方向数 / 方向总数**（不是"命中词数 / 词总数"）。

### ⚑ 标关键词最容易犯的错：按「话题」标，而不是按「模型真会说的词」标

实测过一次：给 seed-02 标了「交通 / 价格 / 美食 / 景点 / 天气」——
模型拆出的是「查询往返机票 / 查询酒店选型 / 查询日元汇率 / 预订接送机 / 购买旅行保险」，
看起来该覆盖的都覆盖了，**而那五个词一个都没中**。

原因：那五个是**话题词**（写给"一篇旅游攻略"的），
而**这个产品输出的是任务图** —— 它说的是「查机票」，不是「交通」。

> **关键词要按"任务"标。** 因为模型拆的是"要做什么"，不是"讲什么内容"。

### ⚑ 两个方向，别只做一个

断言有**两种方向**，而 §8.3 的表格里两种都出现过：

- **必须含**：种子 #1「含'监督学习'」、#2「含 agent/user 分类」
- **不许超过**：种子 #6「只出 1–2 层」、#10「**只出根节点**」、#11「标题 ≤ 12 字」

`node_count` 的 `min` / `max` 就是为第二种留的。

### 数量类的期望：统一用 `{ "min": n, "max": n }`，两边可省

`node_count` 和 `distribution` 里每个 assignee 都走这个形状：

```json
"node_count": { "min": 3, "max": 15 }     // 两头都要
"agent":      { "min": 1 }                // 只要下限
"user":       { "max": 0 }                // 只要上限 —— 就是"不许有 user 节点"
```

⚑ `{ "max": 0 }` 不是笔误，它有用：种子 #1「整理机器学习的知识体系」按判据应当
**全归 agent**（它既不需要去外面动手，也不需要只有用户才有的东西），
所以那条种子可以钉一句"**不许出现 user 节点**"。

⚠️ 但那是**新加的标准**，不是 §8.3 要求的 —— §8.3 给 #1 写的断言只有
"深度 = 3、单根、含'监督学习'"。加之前想清楚：**你真想让"模型误判出一个 user 节点"
就让这条种子变红吗？**（如果是，那它是个不错的探针。）

（`max_errors` / `max_warnings` **不用**这个形状 —— 它们**天然只有上限**，
"至少要有 1 个 error" 没有意义。）

### ⚑ 还有两类（§8.3 里出现过，暂未做进形状）

| 断言 | 出现在 | 打算怎么表达 |
|---|---|---|
| **节点可溯源** | 种子 #3 | 检查节点的 `source_span` 非空 |
| **不超 token 预算** | 种子 #9 | 看 `usage`（`make plan` 已经在打印它了）|

### `must_not_match` 只钉一件事：不许编造（2026-09-22 加的）

它守的是 `§8.3` 的 #6 / #10 那条**文档里早就写了**的期望 ——「**不编造**」：

    #6  `"AI"`        → 不编造、只出 1–2 层
    #10 「最近有点烦」  → 只出根节点，不编造

在这之前它**只有人眼看** ✓。

⚑ 为什么用**正则**而不是关键词：要挡的是"**编出一个具体的值**"这一类，
   而具体的值本来就不确定 —— 只能按【形状】挡
   （`\d{4}[-/年]` 挡"编了个年份"、`\d+\s*人` 挡"编了个人数"）。

⚠️ **它只能挡住最糟的那种错**，挡不住"问得太少"。
   后者是主观的 —— 断言它等于把一种风格焊死，而那会**反过来拦着你改 Prompt**。
   所以 `seed-04` 的 `coverage` 是 `null`（**故意不钉关键词**）。

⚠️ 而且**别只加字段、不加检查** —— 这个文件里已经栽过一次：
   `distribution` 有一阵子是"数据里写着、`runner` 不读它"
   （见 `judge_distribution` 的说明）。新字段进 `corpus.json` 的**同一次**，
   `runner.py` 里必须有人读它 —— 否则它就是个**看着像断言的摆设**。

## ⚑「三层」和「字段」不是同一个轴

`DEV_DOC` §8.1 的三层是**按"贵不贵"**分的：机械数数 / 字符串查找 / 调模型当裁判。

而 `corpus.json` 需要按**"断言什么"**分：结构 / 分布 / 覆盖 / 溯源 / 语义。

**所以字段比"三层"多 —— 这不是矛盾，是两个不同的轴。**
（§8.1 那三层真正回答的是"**什么时候跑哪一层**"。）

## ⚑ 一个 `runner.py` 必须先解决的问题

§8.4 写着「关键指标**退化**？→ 拦截」。那么 —— **"退化"是相对谁说的？**

→ 需要一份**基线**（比如 `evals/baseline.json`）：上一次跑出来的分数。

所以 `runner.py` 不只是"跑一遍"，它还得**记住上次的分数**。否则"退化"根本判不出来 ——
而判不出来，门禁就是个摆设。§8.4 原话：

> **没有回归门禁的评测集 = 摆设。**

## 归属

**12 颗种子的内容**和**三层断言的判定标准**是人的活（§13 第 7 条）。理由原话：

> 「**AI 不知道什么叫"做对了"**」

管子（`runner.py` / `judges.py` / `make eval` / 基线机制）可以交给 AI。
