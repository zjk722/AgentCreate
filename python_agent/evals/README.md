# `evals/` —— 评测（§12 的 **A1**）

**这里放「怎么判断模型吐出来的东西好不好」。**

它**不在 `app/` 里面** —— 评测不是产品代码，不该跟着引擎一起发出去。

> ⚠️ **位置以 `DEV_DOC` §11 为准**：`python_agent/evals/`，与 `app/` **平级**。
> `ARCHITECTURE.md` 的目录树把它画在 `app/` 下面 —— 那是**复制细节必然漂移**的一次实例
> （它在自己开头就警告过这件事）。已记进 v0.7 的清单。

## 文件

| 文件 | 干什么 |
|---|---|
| `corpus.json` | ⭐ **12 颗种子**：题目 + 期望（§8.3）。**内容由人写**（见下面"归属"）|
| `inputs/` | 长文的题目放这儿，`corpus.json` 里只写路径 —— **800 字 / 3000 字的输入塞进 JSON 没法读也没法写** |

## ⚠️ 为什么 `corpus.json` 里没有注释

**JSON 不支持注释。** 所以"每格什么意思、为什么这么定"一律写在这里 ——
和 `shared/README.md` 承接 `tools.json` 是同一个安排。

### ⚑ 两个方向，别只做一个

断言有**两种方向**，而 §8.3 的表格里两种都出现过：

- **必须含**：种子 #1「含'监督学习'」、#2「含 agent/user 分类」
- **不许超过**：种子 #6「只出 1–2 层」、#10「**只出根节点**」、#11「标题 ≤ 12 字」

`node_count` 的 `min` / `max` 就是为第二种留的。

### 数量类的期望：统一用 `{ "min": n, "max": n }`，两边可省

`node_count` 和 `distribution` 里每个 assignee 都走这个形状：

```json
"node_count": { "min": 3, "max": 15 }     // 两头都要
"agent":      { "min": 1 }                // 只要下限
"user":       { "max": 0 }                // 只要上限 —— 就是"不许有 user 节点"
```

⚑ `{ "max": 0 }` 不是笔误，它有用：种子 #1「整理机器学习的知识体系」按判据应当
**全归 agent**（它既不需要去外面动手，也不需要只有用户才有的东西），
所以那条种子可以钉一句"**不许出现 user 节点**"。

⚠️ 但那是**新加的标准**，不是 §8.3 要求的 —— §8.3 给 #1 写的断言只有
"深度 = 3、单根、含'监督学习'"。加之前想清楚：**你真想让"模型误判出一个 user 节点"
就让这条种子变红吗？**（如果是，那它是个不错的探针。）

（`max_errors` / `max_warnings` **不用**这个形状 —— 它们**天然只有上限**，
"至少要有 1 个 error" 没有意义。）

## ⚑「三层」和「字段」不是同一个轴

`DEV_DOC` §8.1 的三层是**按"贵不贵"**分的：机械数数 / 字符串查找 / 调模型当裁判。

而 `corpus.json` 需要按**"断言什么"**分：结构 / 分布 / 覆盖 / 溯源 / 语义。

**所以字段比"三层"多 —— 这不是矛盾，是两个不同的轴。**
（§8.1 那三层真正回答的是"**什么时候跑哪一层**"。）

## ⚑ 一个 `runner.py` 必须先解决的问题

§8.4 写着「关键指标**退化**？→ 拦截」。那么 —— **"退化"是相对谁说的？**

→ 需要一份**基线**（比如 `evals/baseline.json`）：上一次跑出来的分数。

所以 `runner.py` 不只是"跑一遍"，它还得**记住上次的分数**。否则"退化"根本判不出来 ——
而判不出来，门禁就是个摆设。§8.4 原话：

> **没有回归门禁的评测集 = 摆设。**

## 归属

**12 颗种子的内容**和**三层断言的判定标准**是人的活（§13 第 7 条）。理由原话：

> 「**AI 不知道什么叫"做对了"**」

管子（`runner.py` / `judges.py` / `make eval` / 基线机制）可以交给 AI。
